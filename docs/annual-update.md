# 來年沿用與更新

## 只換年度或日期

在編輯器開啟 `data/config.json`。把 `defaultYear` 改為新的民國年度，例如116；`availableYears`已提供115到120。日期填在對應年度的四個欄位，例如：

```json
"dates": {
  "115": ["", "", "", ""],
  "116": ["116/10/11", "116/10/18", "116/11/08", "116/11/15"]
}
```

這四個日期只是格式範例，請換成實際排課。空白時網站顯示「上課日期由教師另行通知」。每堂預設180分鐘。

儲存後啟動本機網站，確認年度、日期及四堂順序。切換116年會使用另一份本機進度，115年進度仍保留。

## 更新題目或解說

在 `data/course.json` 找到對應固定關卡ID，例如 `L2-03`。保留四堂與每堂六關；更新學習目標、來源、互動任務、選項、提示與解說時，需重新核對答案。`question.answer`為從0開始的選項編號：0是第一個選項。

改變題目、答案或過關規則時，更新 `contentVersion`（例如1.0.0改成1.1.0）。網站會按版本分開保存進度；不同版本不會強行匯入，以免舊答案被當成新教材的完成紀錄。保留舊版本標籤及學生匯出檔，讓需要舊紀錄的人使用相同版本。

只改排課日期、錯字與排版，且不影響題意時，可保留教材版本。四堂教材分配是根據114年資料自然分段重建，不能因更新而改寫成已確認的歷史逐堂紀錄。

## 更新合成R練習

依 `labs/README.md`操作，先生成資料再執行分析。合成資料、seed、欄位字典、分析規格及結果一起保留；改變任何一項後重新跑驗證，再更新網頁展示的 `data/lab-results.json`。

不要把原研究資料或未確認授權的PDF放進公開專案；也不要把教學示意公式的輸出標成統計估計。

## 發布與回復

先執行README的語法/狀態檢查，並實際確認手機、投影、闖關、續玩、匯入匯出。確認沒有私人資料後提交main，GitHub Pages會發布更新。到公開網址重新整理並核對圖像與下載。

每次可用版本建立版本標籤。需要回復時，在GitHub比較目前main與先前標籤，以「Revert」建立回復提交，再等Pages完成；保留歷史，不強制覆寫分支。網站回復不會自動回復學生瀏覽器內的進度，使用相同教材版本與匯出備份確認。

教師逐字流程、114來源稽核及驗收證據保存在專案旁的教師資料夾，無須發布到學生網站。
